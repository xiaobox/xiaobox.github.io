![巨型保险柜挂着一把小锁，安全设施与脆弱私钥的反差，概念插画](https://xiaobox-public-images.oss-cn-beijing.aliyuncs.com/images/emudhra-cover-02-tiny-padlock.png)

你平时注册网站或者在公司系统改密码，输入框底下多半会弹出一排红字。

> 「密码长度不少于 8 位，且必须包含大小写字母、数字和特殊符号。」

少凑齐一样，保存按钮都是灰的，死活不让你过。

把普通用户的密码管得这么死，按理说，那些负责保卫整个互联网底层的安全机构，自己的核心密钥应该锁得像**铜墙铁壁**一样。

可就在 10 月 20 号，Cloudflare 发了一份紧急安全公告。保护全球网站 HTTPS 加密连接的**八张顶级中间安全证书**，底层的私钥全被人破解了。

破解它们根本用不着什么超级计算机，随便写个循环从 `1` 往下试，一眨眼就能试出来。因为这八张证书里最小的一把私钥，写成十进制就一个数字。

**`4`。**

对，连两位数都不到，就是一个孤零零的阿拉伯数字 `4`。

很多朋友可能纳闷，一张安全证书的私钥是个 `4`，跟我们平时上网有什么关系。

你现在打开浏览器随便进个网站，地址栏左边那把小锁头，代表你的聊天记录和银行卡号是加密传输的。浏览器怎么确认对面是真的银行、真的购物网站，而不是咖啡馆免费 Wi-Fi 里某个黑客搭的钓鱼后台呢，靠的就是**数字证书机构（CA）**下发的电子公章。

这种机构手里的**「中间证书」**权限极大。谁要是拿到了中间证书的私钥，就能在半路给全世界任何一个域名伪造合法的通行证，把经过的加密流量看得一清二楚。

![中间证书签名权如同电子公章，可被滥用于伪造网站证书，概念插画](https://xiaobox-public-images.oss-cn-beijing.aliyuncs.com/images/emudhra-body-01-signing-authority.png)

为了防住黑客暴力破解，行业规矩定得极严。这次出事的八张证书采用的是 **NIST P-384** 椭圆曲线算法，按标准，它的私钥得是一个高达 **2 的 384 次方**的随机数。

写成我们熟悉的十进制，**足足有 116 位数**，比全宇宙已知原子的总数还要多出几十个数量级。哪怕把地球上所有超级计算机绑一块儿算到太阳熄灭，也别想蒙对一个。

结果印度老牌证书颁发机构 **eMudhra** 签发出来的这八张证书，私钥长度全都在 `3` 到 `8` 个比特之间。

也就是说，这八把本该有一百多位数的核心钥匙，**全都是 256 以内的数字**。

安全研究人员把这八把私钥全试了出来，挨个排在一块儿是下面这串数。

> `4`、`56`、`66`、`115`、`155`、`156`、`230`、`237`

![八把私钥对应的数值依次为4、56、66、115、155、156、230、237，钥匙为概念插画](https://xiaobox-public-images.oss-cn-beijing.aliyuncs.com/images/emudhra-body-02-eight-private-keys.png)

我盯着这串数字看了半天，脑子里就一个念头，这连家里的猫踩键盘都踩不出这么小的数吧。

发现这个漏洞的安全研究员叫 **Wayne**。为了向谷歌、苹果、微软和 Mozilla 证明自己真的拿到了钥匙，他建了个叫 `message.txt` 的文本文件，里面就写了一句话。

> 「We have a problem here, Wayne（我们这儿出问题了，Wayne）」

他用试出来的八把私钥挨个给这个文件生成了加密签名，打包成 `proof.zip` 发给各大浏览器厂商，对方敲一行 `OpenSSL` 校验命令就全明白了。

到了 10 月 20 号，Mozilla 的安全工程师干脆上线了一个叫 `emudhra.we-have-a-problem.com` 的检测网站，**直接拿破解出来的私钥，给该域名底下的十几个测试网址签发了 HTTPS 证书**。你只要访问一下这些测试网址，如果没弹警告还能正常连上，就说明你的设备还在无条件信任这批早就泄密的钥匙。

密码学专家、Go 语言加密库维护者 **Filippo Valsorda** 看到这份签名时第一反应是不敢信，直言这种错误在工程上根本不可能发生。

他顺着那串 `256` 以内的数字往回倒推，还原出了当时的踩坑现场。

正常生成 P-384 私钥的时候，函数接口里需要填一个代表密钥长度的参数，**`48` 字节（也就是 `384` 比特）**。Valsorda 推测，eMudhra 的工程师在调用某个设计得极不安全的底层接口时，八成是把参数含义搞混了，**随手往长度栏里敲了个 `1`**。

计算机老老实实生成一个字节的随机数，上限刚好卡死在 `255`。

BGP.tools 的总监 **Ben Cartwright-Cox** 则给出了另一种推测，他觉得这大概率是哪段测试用的示例代码不小心混进了生产环境。最离谱的地方在于，从生成密钥到签发上线，中间经过那么多道合规审计，**居然没有一个人、没有一行自动化自检脚本发现钥匙短了一百多位**。

漏洞公开之后，主流浏览器和 Cloudflare 在几个小时内紧急下发了吊销补丁，把这八张证书拉进了黑名单。

**但真正的烂摊子才刚刚开始。**

浏览器有现成的热更新通道，可全世界有数不清的软件和设备根本不走浏览器的黑名单。有人实测了一下，发现 Windows 10 上的 Edge 浏览器居然还能正常连上 **12 个受影响的测试节点**。

更别提那些跑在服务器里的老旧 Docker 镜像，还有像 **Python、Node.js、甚至 Claude Code** 这种习惯自己打包一份独立根证书库的开发工具。只要你不手动升级，它们依然会把那八张密码是 `4` 的假证书当成圣旨。Valsorda 甚至觉得，清理这波长尾脏数据的工程量，搞不好比十年前的**「心脏出血」（Heartbleed）**漏洞还要折腾人。

![已更新的环境拦截问题证书，尚未更新的旧环境仍可能放行，概念插画](https://xiaobox-public-images.oss-cn-beijing.aliyuncs.com/images/emudhra-body-03-revocation-gap.png)

如果你手里管着服务器或者平时写代码，现在就可以在终端跑一行命令测一下自己的环境。

```bash
# 1. 自测命令（报 SSL certificate problem 说明已免疫，能正常返回网页说明受影响）
curl --tlsv1.2 https://dv-g3b-emudhra.we-have-a-problem.com/

# 2. Debian / Ubuntu 容器与服务器升级根证书库
apt update && apt upgrade ca-certificates

# 3. Python 环境升级 certifi（需升至 2026.10.19 及以上版本）
pip install -U certifi
```

毕竟在这个连顶级安全机构的私钥都能设成 `4` 的世界里，咱们自己多长个心眼总归不亏。
