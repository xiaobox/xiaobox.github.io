前两天我刚做完一期讲排序算法的视频，折腾了整整 23 分钟的动画，把冒泡、插入、归并、快排一直讲到各家标准库里的 `sort`。

片子剪完刚传上去，今天早上一刷 Hacker News，满屏都在刷同一条消息。

**Tim Peters 走了，74 岁。**

其实老爷子今年 7 月就去世了，只是 Python 之父 Guido 这两天才在官方论坛发了一篇长长的悼文，把消息正式传了出来。

很多刚写代码的朋友可能对这个名字有点陌生。但如果你打开 Python 终端，敲下 `import this`，屏幕上弹出来的《Python 之禅》，什么「优美胜于丑陋，明了胜于晦涩」，就是他在 1999 年顺手写下的 19 条格言。

他留下的远不止一首诗。

我在刚做完的那期视频最后专门讲过一个算法，叫 **Timsort**。就是他 2002 年给 Python 写的，顺手拿自己的名字命了名。

今天你每次在 Python 里调 `.sort()`，每次在 Java 里给对象数组排序，每次滑动安卓手机屏幕，甚至在 Chrome 里跑 JavaScript 的数组排序，底层全在跑他当年写下的这套逻辑。全球几十亿台设备，每天调用成千上万亿次。

但 2015 年发生了一件离谱的事。

这套统治了半个软件工业界的代码里，其实藏着一个能把程序直接干崩的 Bug，**整整潜伏了 13 年没人发现。**

---

事情还得从 2002 年说起。

那会儿教科书里教排序，都在默认一件事，你要排的数据是彻底打乱的随机数字。在纯随机的世界里，快排和归并就是神。

但 Tim 盯着真实世界的数据看了一阵子，发现教科书全在扯淡。

你想想看，现实里咱们排的都是啥？是按时间追加的日志，是差点就排好序的订单表。真实世界的数据根本不是一盘散沙，里头到处都是一段一段已经排好序的「现成小段」。

教科书里的快排看到这些现成的好东西，上来就是一顿乱拆，先把人家原本排好的顺序全搞乱，再费劲巴拉地重新排一遍。

Tim 觉得这太蠢了。

他在 2002 年写出了 Timsort。核心思想特别接地气，先顺着数据扫一遍，把那些原本就排好序的「现成小段」全挑出来。哪一段太短了，就用插入排序从后面借几个数补够长度，然后再像归并那样两两合并。

![把现成有序的小段合并成一条有序序列](https://xiaobox-public-images.oss-cn-beijing.aliyuncs.com/images/timsort-body-1-ordered-runs.png)

我在视频里拿 105 万个像素的画试过，要是数据里本来就有 64 段现成排好的，普通归并得老老实实走 20 轮，**Timsort 只要合 6 轮就收工了。**

这玩意在真实业务里快得像开了挂。2003 年它进了 Python 2.3，后来 Google 工程师 Josh Bloch 看上了它，直接把它搬进了 Java 7 和安卓系统的底层标准库里。

所有人都觉得这段代码无懈可击。毕竟全球几十亿台设备天天在跑，真要有 Bug 早炸了，对吧？

---

直到 2015 年，荷兰国家数学和计算机科学研究所的一帮学者，想找个工业界最经典的算法，用他们搞的形式化验证工具 KeY 来做一次完美的「数学正确性证明」。

他们挑中了 Java 标准库里的 Timsort，本意是拿它当正面教材秀一把肌肉。

结果推着推着，证不出来了。

不仅证不出来，数学工具顺着逻辑漏洞，直接反手给他们构造出了一个必崩的死局。

问题出在哪呢？

Timsort 在合并那些「现成小段」的时候，在内部维护了一个小栈，用来暂存还没合并的段。

为了不让这个栈无限长高，Tim 当年定了一条规矩。每次往栈里塞新段，都要检查栈顶那三段的长度，必须像斐波那契数列那样，下面一段比上面两段加起来还长。如果不满足，就把它们合并掉。

Tim 算了一笔账。既然段的长度至少按斐波那契数列往上涨，哪怕排几百亿个元素，这个栈撑死也就几十层高。所以他在代码里直接把栈的最大容量写死了，比如在 Java 里最多只留 40 到 85 格。

听着天衣无缝，对吧？

但这帮荷兰学者用数学工具死磕的时候，发现了一个盲区。

Tim 写的代码，每次合并完之后，只低头检查了「栈顶最上面的三段」符不符合规矩，却忘了合并动作本身，可能会破坏栈底更深位置的比例关系。

![只盯着栈顶三段，漏掉深处的问题，概念插画](https://xiaobox-public-images.oss-cn-beijing.aliyuncs.com/images/timsort-body-2-stack-blindspot.png)

就是这么一个极微小的疏忽。

只要精心拼凑出一组长短交替的特殊数据，就能骗过栈顶检查，让栈里的段越攒越多，最后直接冲破预留的格子上限，当场抛出数组越界异常，把整个程序干崩。

学者们顺手算出了触发这个崩溃的最短数据长度，**67108864** 个元素，也就是 2 的 26 次方。

消息一出来，整个开源圈都看傻了。大家回头去翻 Python 源码，发现这个 Bug 从 2002 年 Tim 写下第一行代码那天起，就一直安安静静地躺在那里。只是触发条件太苛刻，日常业务根本撞不上。

后来 Java、Android 和 Python 连夜打上了补丁，修法也极其简单，就是在循环检查里多加了一行判断，把栈往深处再看一眼。

---

补丁打上之后，这段代码继续安安静静地跑在全世界的手机和电脑里。

2002 年 Tim Peters 把这套算法写进 Python 源码的时候，在说明文档 `listsort.txt` 的开头给它起了个名字叫 `timsort`。

起完名字，他在后面的括号里敲了一行注释，「hey, I earned it 」。

意思是，嘿，这名字是我应得的。后面还带了个眨眼的表情。

**没错，老爷子，你应得的！ 一路走好。**
