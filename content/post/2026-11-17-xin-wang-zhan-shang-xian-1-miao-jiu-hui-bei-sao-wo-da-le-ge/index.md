很多自己写独立开发项目、或者随手搭个博客和小工具的朋友，心里都有个错觉，觉得我这小破站刚上线，连搜索引擎都没收录，全世界除了我自己没人知道网址，肯定没人来黑我。

我以前也这么想。直到我翻到安全机构 SANS 互联网风暴中心做过的一次实测。

研究员 Bojan Zdrnja 新搭了一个测试站，去申请了一张免费的 HTTPS 证书。在 09 点 34 分 33 秒，这张新证书被登记进了全球公开的证书透明日志（Certificate Transparency）。

下一秒，09 点 34 分 34 秒，第一个访问请求就过来了。

来的人不是顾客，是自动化扫描器。再下一秒，同一个 IP 顺着网线连发了 15 条请求，直奔网站的 `.env` 密码配置文件、`.git/config` 源码仓库配置，还有服务器状态页。

仅仅 1 秒。

为什么会这么快？因为现在全世界的网站只要上 HTTPS，证书下发时就会写进公开账本。成千上万台自动化扫描器 24 小时盯着这本账，你的域名刚配好，它们的探测脚本就已经敲响你服务器的大门了。

那问题来了，怎么挡？

有朋友可能会说，我服务器开了防火墙，前面还挂了 Nginx 和 API 网关，不够用吗？

打个比方，网络请求就像一封信。传统防火墙只看信封表面，查这封信从哪个 IP 来、进哪个端口。API 网关会把信封拆开，看看收件人路径是谁、寄件人有没有身份令牌、发得勤不勤。但信纸上写的那句话本身，比如用户在搜索框里敲的词、留言板里填的话，前面这两道门是不细读的。

专门守在门口、把信纸抽出来逐字逐句读一遍的门卫，就是 WAF，Web 应用防火墙。

听起来很简单对吧？不就是检查用户输入的字符串嘛，写几条正则表达式，「见词就拦」不就完了？

为了试试这个思路靠不靠谱，我在自己电脑的 OrbStack 里开了两台 Ubuntu 虚拟机。一台跑我用 Python 和 SQLite 写的测试小店（11 件商品，含 3 件未上架的内部商品，搜索框故意用字符串拼接 SQL），另一台当攻击机发请求。

没装防护裸奔的时候，我在搜索框敲了一句最基础的 `' or 1=1 -- `。回车一按，库里藏着的 3 件「未上架」商品当场全抖搂出来了。

![](https://xiaobox-public-images.oss-cn-beijing.aliyuncs.com/images/safeline-waf-1-naked-sqli.png)

如果我自己写条正则去拦 `or 1=1`，攻击者只要换成 `' or 2>1 -- `，二大于一同样永远成立，正则当场就瞎了。

你说那我把规则收紧，只要看见单引号 `'`，或者看见 `union`、`select`、`or`、`script` 这些词统统拦下来行不行？

我在测试机上真写了个这样的关键词过滤器，挑了 18 句请求去试（8 句带敏感词的正常话 + 10 句变形攻击）。结果太离谱了。

如果先解码再按词拦，10 句攻击确实拦住了，但 8 句正常话全军覆没。顾客想买个 `Valentine's 礼盒`（带单引号），拦。想搜 `Union Jack 抱枕`（带 union），拦。连在留言板问一句「周五 or 周六发货？」，也因为撞了 `or` 被当成黑客关在门外。反过来，如果直接扫原始 URL 编码串，攻击者只要把空格编码成 `%20` 打断单词边界，10 句攻击直接漏过去 9 句。

写松了漏成筛子，写严了会误杀。

为什么正则这么憋屈？学过编译原理的朋友都知道乔姆斯基文法体系，正则表达式对应表达能力最弱的 3 型文法，它连一串括号到底配没配对都数不清楚。而 SQL 和 JavaScript 全是嵌套的 2 型上下文无关文法。要想既不漏掉变形攻击、又不冤枉买礼盒的顾客，只有一个办法，像编译器一样去「读懂」代码的语义。

这也是国内知名安全厂商长亭科技，在免费开源 WAF「雷池（SafeLine）」里塞进的看家本领，智能语义分析引擎。

雷池不靠死背黑名单。请求进来后，它门口基于 Nginx 的网关先把数据交给检测引擎，先把各种编码彻底还原，再拿内置的编程语言解析器把输入当成 SQL 读出语法树。它只看两件事，第一，这句按 SQL 语法读得通吗？第二，读通了，它想干什么？

顾客搜 `Valentine's 礼盒`，单引号后面的字母根本接不成合法 SQL，放行。输 `1+1=2`，虽合语法但什么都没干，放行。可一旦输入 `' or 2>1 -- `，语法树一看这小子在把查询条件改成恒真，当场盖章 403 拦截。

![](https://xiaobox-public-images.oss-cn-beijing.aliyuncs.com/images/safeline-waf-2-semantic-deny.png)

光看原理不够过瘾，我直接在小店虚拟机里试了一把真实部署。

雷池社区版对配置要求不高，Linux 装好 Docker，1 核 2G 就能跑。官方给了一行一键安装命令，

```bash
bash -c "$(curl -fsSLk https://waf-ce.chaitin.cn/release/latest/manager.sh)"
```

敲下回车选安装，目录一路默认，拉起 7 个容器到能登录控制台，我这台虚拟机实测耗时 3 分 19 秒。进 9443 端口控制台点「添加应用」，把 80 端口交给雷池、上游填小店内网地址，不到一分钟就接好了，顾客访问页面没有任何感知。

![](https://xiaobox-public-images.oss-cn-beijing.aliyuncs.com/images/safeline-waf-3-app-console.png)

接好后全程保持默认配置，一条规则没调，我把刚才那 18 句测试集重跑了一遍。

8 句带 `union`、`select`、`or`、单引号的正常话，雷池 0 误拦，全部放行。10 句带注释符分割、大小写混写、URL 编码的 SQL 注入和 XSS 攻击，100% 拦下。（顺便说个好玩的事，`Valentine's 礼盒` 雷池放行了，小店自己却报了 500 错误，因为小店代码没转义单引号把 SQL 拼崩了。毕竟 WAF 守的是门口，不替你修代码 Bug，但在你改完祖传代码前，门口先有人挡着能救命。）

![](https://xiaobox-public-images.oss-cn-beijing.aliyuncs.com/images/safeline-waf-4-attack-logs.png)

接着我又开起攻击机上的两个主流扫描器 nikto 和 nuclei，对着小店轰了 9557 个请求。

雷池从里面精准揪出了 284 个攻击事件（其余九千多个只是盲猜不存在的文件名，小店直接回 404）。凡是夹带了目录穿越、命令注入、XSS，或是偷看 `.git/config`、`.svn/entries` 的请求，全被记进攻击日志，连上游服务器的 `Server` 版本头都顺手帮你藏了起来。

除了读懂语义，防刷和防爬也没落下。我打开 CC 防护里的「基础访问限制」（10 秒内请求达 100 次就触发人机验证），在攻击机上花 2.15 秒连刷了 120 次首页，几秒后再用浏览器访问，直接被拦下来要求做人机验证。如果把 BOT 防护里的动态防护也勾上，雷池还会在每次打开网页时动态加密 HTML 和混淆 JS，每次看代码都换个长相，专治各种爬虫。

![](https://xiaobox-public-images.oss-cn-beijing.aliyuncs.com/images/safeline-waf-5-cc-challenge.png)

最良心的是，上面演示的语义分析、CC 限频、人机验证、身份认证、动态防护，在雷池个人版（社区版）里全部永久免费。独立开发者和个人站长护住自己的小站，完全够用。

可要是这家小店越做越大，真做成了公司业务呢？

那时候需求就不一样了。比如站点超过了个人版 10 个的上限，大促高并发需要把单线程切换成吃满多核的「极致性能模式」，或者在门口给多台后端服务器做负载均衡。

![](https://xiaobox-public-images.oss-cn-beijing.aliyuncs.com/images/safeline-waf-6-pro-dashboard.png)

又比如半夜被扫没人盯控制台，需要把攻击告警直接推到钉钉、飞书、企业微信群里。或者公司只做国内业务，想按地理位置一键把所有境外 IP 请求挡在门外，再配上每天自动更新的加强版恶意 IP 威胁情报（官方在线演示站上，光这一条规则一天就能挡下八千多次请求）。

![](https://xiaobox-public-images.oss-cn-beijing.aliyuncs.com/images/safeline-waf-7-pro-notify.png)
